* **보험 약관 (영문 표현)**

## 2. 하이브리드 검색기(Retriever) 파이썬 코드 분석

### ① 방어 코드 (Early Return)
```python
if not vector_hits:
    return []
```
* **의미:** 검색된 결과(`vector_hits`)가 비어있다면(`[]` 또는 `None`), 불필요한 후속 연산(리랭킹 등)을 하지 않고 즉시 빈 리스트를 반환하며 함수를 종료합니다.

### ② 한국어 토크나이저 (정규표현식 기반)
```python
@staticmethod
def _tokenize_ko(text: str) -> List[str]:
    return re.findall(r"[가-힣a-zA-Z0-9]+", text.lower())
```
* **역할:** 키워드 검색(BM25)을 위해 모든 특수문자와 공백을 제거하고 한글, 영어(소문자 통일), 숫자 덩어리만 추출합니다.
* **장점:** 형태소 분석기를 쓸 때 `'제15조'`나 질병 코드 `'I60'`이 잘게 쪼개지는 현상을 막고 원형 그대로 빠르게 보존합니다.

### ③ BM25 순위(`rank`)와 원본 위치(`idx`) 매핑
```python
for rank, idx in enumerate(
    sorted(range(len(candidate_docs)), key=lambda i: bm25_scores[i], reverse=True)
):
```
* **동작 원리:**
  1. `sorted(...)`: 문서 내용이 아닌 **문서의 원래 인덱스 번호(`idx`)**를 BM25 점수가 높은 순으로 정렬합니다.
  2. `enumerate(...)`: 정렬된 순서대로 0등, 1등, 2등... **순위(`rank`)**를 매깁니다.
* **목적:** 추후 벡터 검색 순위와 합산(RRF 알고리즘)하기 위해, 특정 순위(`rank`)가 원래 몇 번째 문서(`idx`)인지 연결 고리를 만듭니다.

## 3. 벡터 DB 선택: Milvus 대신 Qdrant를 쓰는 이유

* **Collection(컬렉션)이란?** RDBMS의 '테이블'과 같은 개념으로, 동일한 차원의 벡터 데이터와 메타데이터(Payload)를 모아두는 보관함입니다.

| 비교 항목 | Qdrant | Milvus |
| :--- | :--- | :--- |
| **개발 언어** | **Rust** (가볍고 빠른 성능) | Go / C++ (대규모 분산 처리 초점) |
| **인프라/배포** | **단일 컨테이너**로 즉시 실행 가능 | etcd, MinIO 등 부속 컴포넌트 다수 필요 |
| **필터링 성능** | **매우 뛰어남** (HNSW 탐색 중 필터 동시 적용) | 대규모에선 강하나 소규모에선 오버헤드 존재 |
| **추천 규모** | 수만 ~ 수천만 건 (대부분의 기업용 RAG) | 수억 ~ 수십억 건 이상의 초대규모 데이터 |

* **보험 약관 프로젝트의 핵심 장점:** `query_filter=strict_filter`(보험사, 상품명, 가입 연도 등) 조건을 걸 때 검색 속도 및 정확도 저하가 적고 운영이 매우 가볍습니다.

## 4. 파인튜닝 데이터 확보 3단계 파이프라인

1. **1단계: 실제 기출문제 수집 (Seed 데이터, 200~300건)**
   * 실제 콜센터 상담 이력에서 개인정보를 마스킹하고 질문+모범 답변 추출 (현장감, 자연스러운 구어체 담당)
2. **2단계: AI 기반 합성 데이터 대량 생성 (Data Augmentation, 1,000건+)**
   * 고성능 모델(GPT-4o 등)을 활용해 약관 청크 기반 고객용/직원용 Q&A 대량 출제
   * **비율:** 단순 조항 질의(60%) + 본문/[별표] 복합 계산 질의(25%) + 거절 유도 질의(15%)
3. **3단계: 자동 검증 및 필터링 (Quality Filtering)**
   * 심판 AI(LLM-as-a-Judge)로 원본 약관에 없는 숫자나 조항을 지어낸 환각(Hallucination) 데이터를 걸러내고 최종 JSONL 생성
* 👉 **최종 학습:** 1단계(실제 데이터)와 2~3단계(검증된 합성 데이터)를 합쳐서 파인튜닝에 사용합니다. (일부는 평가용 Test 셋으로 분리)

## 5. RAG에서 파인튜닝을 하는 진짜 이유 (RAFT 원리)

* **목적:** 약관 내용을 암기시키는 것이 아니라, **"오픈북 시험(RAG)에서 주어진 약관을 읽고 정확히 대답하는 요령"**을 가르치는 것입니다.
* **데이터 구조:** `[참고 약관(Context)] + [질문(Question)] ➔ [답변(Answer)]`의 3단 구조로 훈련합니다.
* **핵심 동작 원리 (어텐션 & 오답 필터링):**
  1. **형광펜 효과(Self-Attention):** LLM이 질문의 핵심 키워드와 일치하는 약관 조항에만 높은 가중치(스포트라이트)를 줍니다.
  2. **노이즈 제거 & 거절 학습:** 검색기가 가져온 3~5개의 약관 조각 중 엉뚱한 조항(오답)은 무시하고 정답 조항만 조합해 답하며, 근거가 아예 없으면 *"약관에 근거가 없어 답변할 수 없습니다"*라고 거절하는 안전장치를 학습합니다.
